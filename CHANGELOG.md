### Добавлено
- 2026-11-13: Демо онлайн на бесплатном хостинге Render: <https://hackaton-pavlodar-hub-modus-2026.onrender.com/>. Ссылка вверху README и в разделе «Как смотреть демо», там же — чем онлайн-версия отличается от локальной.
- 2026-11-12: Привязка Telegram по QR-коду: в профиле рядом с кнопкой показан QR-код с той же одноразовой ссылкой, чтобы привязать аккаунт со страницы, открытой на компьютере. QR-код рисует наш сервер (новая зависимость `segno`), код не уходит во внешние сервисы. Страница профиля сама замечает привязку и обновляется. 3 новых теста, всего 83.
- 2026-11-12: Пользовательские истории (`docs/user-stories.md`): 42 истории по ролям с метками этапов; как сотрудники остаются мотивированными (путь автора, признание вместо денег и квот, мотивация ответственных) и что не даёт процессу заглохнуть (что держит система, ритм разборов, метрики здоровья процесса, первые 90 дней). В план следующего этапа добавлена доля авторов, подавших второе обращение (`docs/solution-design.md`, раздел 11).
- 2026-11-12: Снимки экранов с телефона (`docs/screenshots/11–13`) и раздел о них в README. Все страницы проверены на ширине 390 px.
- 2026-11-12: Проверки вживую: Telegram-бот (привязка аккаунта одноразовым кодом, доставка уведомлений) и Docker-образ (собирается, в контейнере проходят все 80 тестов). Из README и документов убраны пометки о том, что это не проверялось.
- 2026-11-12: Работающий MVP на Django 5.2 и SQLite (`feedback/`, `config/`, `manage.py`): подача обращения с квитанцией, маршрутизация по 16 правилам с цепочкой замещения, статусы и переписка с автором, сроки в рабочих днях, автоматическая эскалация, подтверждение результата автором, поиск и фильтры, сводка для руководства, лента «Сделано», конфиденциальный режим, регистрация со слов сотрудника, «у меня тоже» и объединение дубликатов.
- 2026-11-12: Ядро и подключаемые интеграции в коде: журнал исходящих событий, диспетчер с повторами и запасным каналом, Telegram-бот (уведомления и привязка аккаунта), имитация Битрикс24 (запись REST-запроса `im.notify.system.add`, импорт справочника из файла), страница «Интеграции» с переключателями и журналом.
- 2026-11-12: Демо для жюри: главная страница с шестью сценариями организаторов, переключатель ролей, демо-часы («+1 раб. день»), сброс данных. Демо-данные (`data/`): справочник в формате Битрикс24, правила, 14 дополнительных обращений и история каждого обращения в относительном времени.

### Изменено
- 2026-11-12: В начале README — раздел «Для жюри»: кратко о решении, список документов (перенесён из конца README) и таблица «что требует ТЗ — где смотреть» со ссылками на нужные разделы документов, включая три вопроса ТЗ §6.
- 2026-11-12: Таблицы на телефоне: в карточке у каждого поля теперь есть подпись. Раньше в списке обращений автор и ответственный выглядели одинаково — имя и подразделение без заголовка.
- 2026-11-12: Описание решения и ценностное предложение приведены в соответствие с тем, что реализовано: метка «MVP» теперь означает «реализовано в работающем MVP»; подтверждение результата автором, лента «Сделано», похожие обращения и «у меня тоже» перенесены в MVP; нереализованное (изменение категории после подачи, дайджесты, черновики, файлы перевода) перенесено на следующий этап; эскалация описана как фоновая проверка с записью в историю (`docs/solution-design.md`, `docs/value-proposition.md`).
- 2026-11-12: Выбран стек: Django 5.2 LTS, SQLite в демо и PostgreSQL в эксплуатации, страницы собираются на сервере (`docs/technical-concept.md`, раздел 5).
- 2026-11-12: Оригиналы от организаторов (`docs/source/`) исключены из git; в репозитории остаются их Markdown-версии.
- 2026-11-12: Рабочие материалы команды (анализ, проверка соответствия ТЗ, расшифровка видео, исследование) перенесены в `docs/internal/` и вместе с инструкциями для ИИ-агентов исключены из git. Источники цифр для слайдов перенесены прямо в `docs/value-proposition.md`. README указывает на документы для жюри.
- 2026-11-12: Архитектурный принцип «ядро и подключаемые интеграции»: ядро работает без интеграций, каждая включается и выключается отдельно, решение работает самостоятельно и модулем внутри Битрикс24 (`docs/solution-design.md`, раздел 7.2; `docs/value-proposition.md`).
- 2026-11-12: К Битрикс24 не подключаемся: доступа к порталу заказчика нет. Добавлен механизм интеграций на нашей стороне — адаптеры, журнал исходящих событий, имитатор Битрикс24 со страницей «Журнал интеграций», импорт справочника из файла в формате Битрикс24 (`docs/solution-design.md`, раздел 7.2).
- 2026-11-12: Подтверждено, что портал Битрикс24 облачный: интеграция только через REST API, вебхуки и приложения (`docs/solution-design.md`, разделы 7 и 12).
- 2026-11-11: Маршрутизация по правилам, как требует ТЗ §2.3: правила по типу, категории и подразделению автора назначают роль; резервная цепочка на время отсутствия; правило по умолчанию; «Не моё» заново применяет правила. Категория стала обязательной, с подсказкой по тексту. Роль «Диспетчер» заменена на «Координатора», который разбирает только исключения. Демо-правила выведены из датасета (`docs/solution-design.md`, раздел 3.1).
- 2026-11-11: Решение проектируется для одной страны — Казахстана: один экземпляр, данные в Казахстане, казахстанский календарь и UTC+5 в настройках. Вариант с двумя странами (Россия и Казахстан) снят.
- 2026-11-11: README и журнал изменений ведутся на русском; английские версии — в файлах с суффиксом `.en.md`.
